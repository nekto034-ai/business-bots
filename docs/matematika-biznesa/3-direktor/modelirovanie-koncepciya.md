# «Моделирование» и «было → стало» — концепция v2 (после разбора образца)

## Отзыв Артёма на образец v1
- Много цифр, разбросано, выглядит как дешёвая кликбейтная реклама.
- Непонятно, откуда цифры и как их контролировать.
- Цифры на брифе — примерные; точные появляются только после установки CRM.
- Формат передачи клиенту не определён (ссылка, PDF, видео).

## Главный принцип: честность цифр
Каждая цифра подписана источником:
- **«со слов»** — клиент сказал на созвоне;
- **«оценка»** — посчитали по формуле из его слов;
- **«факт из CRM»** — измерено после внедрения.

## Три точки вместо двух
| Точка | Когда | Откуда цифры | Что показываем |
|---|---|---|---|
| 0. Оценка | Созвон по брифу | Со слов клиента | Схема процесса + где риски + оценка потерь |
| А. Фотография | Первый месяц после внедрения | Факт из amoCRM | «Впервые видите свои реальные цифры» |
| Б. Результат | 2–3 месяца после внедрения | Факт из amoCRM | Сравнение с точкой А |

Для клиентов без CRM честное «было → стало» = А → Б. Точка 0 — только для продажи, с пометкой «оценка».
Сама видимость цифр — уже ценность: клиент обычно их вообще не видит.

## Как amoCRM измеряет каждую метрику
| Метрика | Как считаем в amoCRM | Что нужно настроить |
|---|---|---|
| Заявок в месяц (по каналам) | Новые сделки за период по источникам | Источник у каждой сделки (интеграции, теги, UTM) |
| Время первого ответа | От создания сделки до первого исходящего сообщения/звонка. Частично в стандартных отчётах, точно — расчёт по событиям через API | Все каналы и телефония внутри amoCRM |
| Потерянные заявки | (а) закрытые с причиной «не ответили / не дозвонились / пропал»; (б) открытые сделки без задачи или без активности 3+ дня | **Обязательная причина отказа** при закрытии + правило «у каждой сделки есть задача» |
| Конверсия | Успешные ÷ все за период | Этапы «Успешно» / «Не реализовано» используются всегда |
| Средний чек | Бюджет успешных сделок ÷ их число | Поле «Бюджет» заполняется обязательно |

Ключ к честной статистике — **обязательные причины отказа** и **бюджет** в каждой сделке. Это входит во все пакеты.
Что считается «потерянной заявкой» — фиксируем определением и показываем клиенту заранее.

## Формат для клиента (предложение)
1. **PDF на 1 страницу (A4)** — открывается в любом мессенджере, можно переслать партнёру/бухгалтеру. Генерируется из шаблона.
2. **Голосовое или видео 1–2 минуты** — Артём своими словами проходит по схеме. Личный контакт, дёшево по времени.
3. Веб-страница — позже, для отчётов «было → стало» из CRM.

## Принципы визуала (v2)
- Одна страница, одна главная картинка — схема процесса клиента с 2–3 отметками проблем.
- Не больше 3–4 цифр, у каждой подпись источника.
- Спокойный деловой тон, без крупных красных сумм и восклицаний.
- Структура: Ваш процесс → Что мы услышали → Оценка → Что предлагаем → Как будем измерять.

## Уточнения Артёма (v3) — ВАЖНО

### Два разных продукта — разные акценты
| | **Моделирование** | **Было → стало** |
|---|---|---|
| Когда | До продажи, после брифа | После внедрения, ежемесячно |
| Цифры | Примерные, со слов клиента | Факт из amoCRM |
| Задача | Подсветить, что есть потенциальная проблема | Видеть цифры, контролировать, работать с ними |
| Обещание | «Мы сделаем так, что вы будете видеть эти цифры» | «Вот ваши цифры, вот что изменилось, вот что делать дальше» |
| Продаёт | Внедрение | Продление сопровождения |

### Главная идея — формула «Математика бизнеса»
Нет обращений → нет заявок → нет сделок → нет денег. Люди смотрят только на деньги, а управлять можно только тем, что до них.
**Деньги = Обращения × Конверсия × Средний чек (× Повторные покупки)**
Это и есть смысл названия компании и основа позиционирования. Никто из клиентов с этими цифрами не работает — мы делаем их видимыми.

### Масштабирование: как это будут делать сотрудники (не Артём)
| Этап | Как делается | Кто |
|---|---|---|
| v0 — сейчас | Артём проводит бриф, присылает ответы, Claude собирает PDF | Артём + Claude |
| v1 | Веб-форма на нашем сервере: продавец вносит ответы во время созвона → формула и шаблон → готовый PDF за минуту | Любой продавец |
| v2 | Ответы брифа — поля в сделке в собственной amoCRM; кнопка/вебхук → сервер генерирует PDF и прикрепляет к сделке | Любой продавец |
| v3 | «Было → стало»: сервер раз в месяц забирает цифры из amoCRM клиента по API и собирает отчёт; сотрудник проверяет и отправляет | Сотрудник техподдержки |
Основа — шаблон + формула, ИИ не обязателен. ИИ можно добавить позже для текста рекомендаций.
Видео/голосовое — по желанию, по готовому сценарию на 1 минуту.
